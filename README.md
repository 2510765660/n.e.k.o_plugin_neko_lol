# 英雄联盟陪玩（neko_lol）

给 N.E.K.O 桌宠加一个英雄联盟陪玩插件：局内关键事件播报、定期战况小结、
赛后总结，并且可以在聊天里直接问当前战况。

- **插件 ID**：`neko_lol`
- **入口类**：`plugin.plugins.neko_lol:NekoLolPlugin`
- **数据来源**：Riot 官方 **Live Client Data API**（`127.0.0.1:2999`），只读
- **支持区服**：国服（WeGame）与国际服通用；接口先试 https 再回落 http

---

## 安全边界（先看这段）

本插件**只读**官方文档化的本地接口：

```
https://127.0.0.1:2999/liveclientdata/allgamedata
https://127.0.0.1:2999/liveclientdata/eventdata
```

它**不做**这些事：不读游戏进程内存、不注入 DLL、不 hook 客户端、不发送
任何操作指令、不碰反作弊。这是 Riot 官方给第三方应用留的接口，和那些会
被封号的路线是两回事。

只有一件事需要注意：端口 2999 只在**进入对局之后**才存在。大厅、选人、
结算阶段连不上是**正常状态**，不是故障——插件把连接被拒当成"主人现在没在
打"来处理，不会报错、不会刷日志。

---

## 安装

这是按 N.E.K.O「插件制作工作台」的外部插件项目做的，**不需要**克隆主仓库、
不需要 uv、不需要改发行版目录：

1. 打开 N.E.K.O → 插件管理器 → 左侧「**插件制作工作台**」
2. 点「**添加已有项目**」，选到这个目录（含 `plugin.toml` 的那一层）
3. 回插件列表，找到「英雄联盟陪玩」，**手动点启动**

> 工作台登记的项目**永远不会自动启动**，每次开 N.E.K.O 后要手动点一下。
> 想让它开机自启，得走插件 CLI 打包成 `.neko-plugin` 正式安装。

装好后先做两件事：

1. 在插件详情里调用一次「**连接自检**」入口 —— 如果此刻没在打游戏，
   它会如实报告"端口没响应"，这是对的；开着游戏调用则应该能读到对局时间。
2. 建议第一局先把 `dry_run` 打开（见下文配置），只让它写日志不说话，
   确认事件识别准确了再关掉。

## 用法

### 局内自动播报

进入对局后自动开始。**只播报主人自己的事** —— 队友拿人头、队友被杀、
对面互杀都不说；一血只在「主人拿到」时播报。

播报分**三档**，区别只在"什么时候说"：

| 档位 | 事件 | 投递 |
|---|---|---|
| **关键** | 超神、团灭、大龙、赛后总结、对局结束 | 永远立刻说，间隔再密也不等 |
| **常规** | 开局、一血、击杀、阵亡、别人的三杀以上、小龙 | 立刻说，但与上一条至少隔 `normal_gap`（默认 3 秒） |
| **环境** | 峡谷先锋、推塔、破兵营、定期小结、辅助位助攻 | 进窗口合并，安静 `window_seconds`（默认 10 秒）后一起说 |

关键档插进来**不会**打断窗口——窗口按自己的倒计时走，不会被提前触发。
常规档如果离上一条太近，不丢弃，而是和低档一起进窗口合并。

**唯一的例外是 `GameEnd`**：对局都结束了，窗口里再攒着也不会有机会说，
所以它先把窗口结算掉，紧接着播"这局结束了"，5 秒后再播赛后总结。

### 大乱斗降噪

大乱斗（嚎哭深渊）人头密度是峡谷的 3~4 倍、时长只有一半，照搬峡谷的规则
一局能播 30~45 条人头播报，所以单独降噪：

| 规则 | 峡谷 | 大乱斗 |
|---|---|---|
| 人头/阵亡档位 | 常规档（够间隔就立刻说） | **环境档**（进窗口合并） |
| 阵亡播报 | 每次都播 | **只播有信息量的** |
| 爆发小结门槛 | 5 人 / 30 秒 | **8 人 / 30 秒** |
| 爆发小结冷却 | 60 秒 | **120 秒** |
| 定期小结 | 15 分钟首播、每 5 分钟 | 8 分钟首播、每 3 分钟 |

**"有信息量的死亡"** 指两种：

- 死前有 **≥3 连杀** 被断 → `…，连杀被断了（本来 5 连杀）`
- **20 秒内连着倒下第二次** → `…，这波连着倒了两次`
  （只在凑成第二次那一刻播一次——连死五次不会播五条）

```toml
aram_kills_ambient = true
aram_death_only_notable = true
aram_burst_kills = 8
aram_burst_cooldown_seconds = 120.0
```

### 爆发小结

除了定时小结，**15 分钟后**如果 30 秒内（不分敌我）打满 5 个人头，会补播一次
小结——团战刚打完正好报个战况。

- 人头**两边一起算**：团战两边都在死人，只数一边会漏掉真正的大团
- 两次之间至少隔 `summary_burst_cooldown_seconds`（默认 60 秒）
- **同一拍里有团灭就跳过**：团灭本身已经把这一波说清楚了，再来一条"当前战况"
  是重复
- 定时小结和爆发小结**共用冷却**，所以第 15 分钟那一刻两者不会连着播

```toml
summary_burst_after_seconds = 900.0    # 15 分钟后启用
summary_burst_kills = 5                # 窗口内人头数
summary_burst_window_seconds = 30.0    # 统计窗口
summary_burst_cooldown_seconds = 60.0  # 两次之间至少隔多久
```

### 分路里程碑

按主人所在分路给**阶段性**播报，而不是每次击杀都开口。全部要求
**召唤师峡谷 + 征召模式 + 分路可信**，普通匹配/大乱斗一律不触发。

| 分路 | 条件（用户 2026-11-16 指定） |
|---|---|
| **上单** | 15 分钟内**对位单杀 3 次**，且全程**没被对位那个人击杀或参与击杀** |
| **打野** | **全队人头超过 10**，且**主人参与度 ≥ 60%**（击杀+助攻 / 全队人头） |
| **中单** | 12 分钟内完成 **5 次转移击杀**（我助攻、击杀者不是我、被杀的不是我对位） |
| **ADC** | 20 分钟前**补刀领先对面 ADC 50** |
| **辅助** | 第 **10 / 20** 个助攻各播一次 |

播报只讲**成绩**，不复述上面这些判定条件（"15 分钟前""3 次"这类是代码里
的判定，念出来像在读说明书）。实际播报长这样：

> 主人上路打穿了，铁血狼母 已经被单杀三次。
> 主人这局节奏带得好：全队 20 个人头里，主人参与了 12 个。
> 主人中路游走很凶，队友的人头里有 5 个是主人帮出来的。
> 主人补刀压得很死，对面 ADC 已经被甩开 60 刀了。
> 主人已经 10 个助攻了，这局跟团和保人做得很好。

上单报的是**英雄名**而不是玩家昵称。

- 每条里程碑**一局只播一次**（辅助是 10 和 20 两次）。
- 走**环境档**，但**不参与窗口合并**：里程碑是"状态总结"而非"刚发生的事"，
  合进"刚才发生了这些事"会被模型当成并列事件讲（实测踩过：击杀 + 10 助攻
  里程碑被拼成一句"刚才发生了这些事"）。所以它独立成条。
- 上单的"对位单杀"要求**没有助攻**：有人帮忙的击杀不算单杀。
- 上单一旦被对位选手击杀（或他对你的击杀有助攻），本局里程碑直接失效，
  日志和面板都会写出来。

> ⚠ 这些指标都建立在"同队数组顺序 = 分路顺序"上。接口不给队列类型，
> 排位和普通匹配在 `gameMode` 层面都是 `CLASSIC`，无法区分。普通匹配没有
> 位置选择流程、顺序不保证，**可能把非辅助玩家当成辅助、把随机顺序当成
> 分路**。常玩普通匹配请关掉 `infer_lane_positions`（里程碑和分路播报会一起停）。

面板会显示当前进度（例如「对位单杀 2 / 3」「补刀 180 对 120」），
不用等播报才知道差多少。

### 辅助位的助攻播报

辅助很少拿人头，只播「主人击杀」的话一整局几乎不吭声。所以**判定主人是
辅助位时，队友拿的人头只要主人在助攻名单里，也播一句**：

> 主人助攻，星籁歌姬 拿下了对面的 诺克萨斯之手。

触发条件必须**同时**成立：

- 召唤师峡谷 + 征召模式（`lanes_trusted` 已经把这两层卡住）
- `infer_lane_positions = true`，且同队顺序里主人排第 5 位（辅助）
- `only_my_events = true`（否则队友人头本来就会播，重复）
- 面板上的「主人助攻（辅助位）」开关没关

走**环境档**，会进窗口合并——辅助一局助攻十几二十次，逐条播是灾难。

> ⚠ 接口不给队列类型，排位和普通匹配在这一层无法区分。普通匹配没有位置
> 选择流程，顺序不保证，**可能把非辅助玩家误判成辅助**。常玩普通匹配的话
> 请把 `infer_lane_positions` 关掉（顺带也不会再误播分路）。

合并成一条的播报在日志和 `meta` 里用独立的 key `merged`，不借用任何
真实事件的 key。组成它的每一条在提交时已经各自过了开关，所以关掉
「推塔」不会连带把「推塔＋兵营」的合并播报静音（那两条本来就已经
分别在提交时被挡掉了）。

合并的几条规则（2026-11-17 修订）：

- **按到达顺序拼接**，不按优先级重排。优先级只决定截断时谁被丢掉。
  早先按优先级排序，于是建筑播报被念成「兵营 → 二塔 → 高地塔」——
  塔是从外往里塌的，倒着念很别扭。
- **重复的句子标次数**：两座门牙塔是「（2 座）」，同一个英雄被连杀
  两次是「（2 次）」。早先人头重复会被直接吞成一条。
- **助攻约束会一起带过来**：合并里只要有助攻数据，提示语就补上
  「助攻只作背景，不用特意点名谁帮的」。早先这条约束只存在于单条
  提示语里，合并时被丢掉，反而更容易念出助攻名单。

```toml
normal_gap_seconds = 3.0    # 常规档两条之间的最小间隔
window_seconds = 10.0       # 环境档攒多久
```

### 播报示例

| 事件 | 播报 |
|---|---|
| 对局开始 | 主人刚开了一局英雄联盟（召唤师峡谷·经典）。主人玩的是 盖伦。主人走**上单**，对位的是对面的 **德莱厄斯**。 |
| 一血 | 主人拿到了一血！ |
| 主人击杀 | 主人击杀了对面的 亚索 |
| 主人阵亡 | 主人被对面的 劫 击杀了 |
| 团灭 | 主人这边团灭了对面！ / 主人这边被团灭了 |
| 小龙 | 主人拿下了火龙。 / 队友拿下了火龙。 / 敌方拿下了火龙。 |
| 大龙 | 队友拿下了大龙（是抢的！） |
| 推塔 | 主人拆掉了对面的上路外塔。/ 敌方拆掉了我们的下路二塔。 |
| 破兵营 | 敌方拆掉了我们的中路兵营。 |
| 定期小结 | 峡谷：第 **15** 分钟首播、每 5 分钟；大乱斗：第 **8** 分钟首播、每 3 分钟 |
| 爆发小结 | **15 分钟后**，30 秒内 ≥5 个人头时补播一次，冷却 60 秒 |
| 对局结束 | 这局结束了。（**不提输赢、不带战绩行**） |
| 赛后总结 | 对局结束：召唤师峡谷·经典，时长 00:25:20，赢了。+ 完整战况 |

**英雄称呼**：接口给的是中文官方全称（「虚空恐惧」「诺克萨斯之手」），播报
尾巴会明确要求模型「别照搬官方全称，用玩家平时的叫法」，并给一个例子。
插件不做内置映射表；想连直出文本也固定成口语，用可选的
`champion_aliases.json`（见下文）。

### 结束播报与赛后总结

**对局结束**（`GameEnd` 到达时立刻说）：

> 这局结束了，赢了。

早先这里只说"这局结束了"、把胜负留给 5 秒后的赛后总结，代价是中间有
5 秒静默，听感上像卡住了。现在这里直接说结果。

**赛后总结**（5 秒后）只讲过程，**明确要求不重复输赢**：

> 对局结束：召唤师峡谷·经典，一共打了 37 分 58 秒，赢了。
> 主人：虚空恐惧，13—3—8，16 级
> 装备：3 件（兰德里的苦楚、深渊面具、明朗之靴）
> 我方击杀 25，敌方击杀 28（我方落后 3 个），我方拆了 9 座塔、敌方拆了 4 座（塔数占优）
> 人头王：虚空恐惧 13 杀（我方）
> 助攻王：星籁歌姬 16 助攻（我方）
> 主人对位：虚空恐惧 13—3—8 对 齐天大圣 9—6—5
> （胜负刚才已经说过了，这里不要再重复输赢，重点讲过程和数据。）

几个细节：

- **时长说人话**：`37 分 58 秒`，不再是 `00:37:58`（后者容易读成"零点三十七分"）
- **装备**：满 6 件说「六神装」，否则说「N 件（前三件）」
- **塔数解释局面**：人头落后但塔多时会标「（塔数占优）」—— 偷家赢下来的
  局就不会被解释成"虽然落后但还是赢了"这种别扭话
- **高光**：人头王 / 助攻王 / 主人对位对比，全部从当前快照算，不猜
- **一次没死**会单独提一句

塔数接口不给，由插件自己数 `TurretKilled` 事件（`[塔] ally 第 N 座` 会写日志）。

**比分行**：只用击杀数，并且直接给出领先/落后：

> 比分：我方击杀 26，敌方击杀 22（我方领先 4 个）。

**不再是三段式**。早先写成 `我方 26—26—35 · 敌方 22—31—20`，实测模型会把
第二个数（阵亡）当成击杀去比，把「领先 4 个」说成「落后」——两行的前两位还
恰好互补，扫一眼就换位。详细信息仍在上面「主人 / 队友 / 敌方」那几行里。

**战绩格式**：播报里的数字是「击杀—死亡—助攻」（例如 `3—1—2` 表示
3 杀 1 死 2 助攻）。带战绩的提示语里会自动附上说明，并且**要求模型把中间的
横线念成「杠」**（`3—1—2` 读作「三杠一杠二」）—— 否则容易念成"三到一"、
"三减一"，或者干脆跳过。

**谁能拿的**统一说「主人 / 队友 / 敌方」，靠开局快照里 `allPlayers` 的
`team` 字段映射。查不到的人说「有人」，不瞎猜阵营。

**非英雄击杀**：被防御塔、小兵、野怪打死时不会把结构物内部 ID 念出来
（实测踩过「主人被对面的 `Turret_TChaos_L1_P3_2254202041_0` 击杀了」）。
会降级成「主人被防御塔击杀了」；认不出的长 ID 说「非英雄单位」。
这类播报不带「对面的」——防御塔没有阵营可言。

**击杀播报里的分路**：只在**排位/灵活排位**（峡谷 + 征召 + 开了
`infer_lane_positions`）时，给提示语里的英雄名补一个分路后缀：

```
主人击杀了对面的 劫（中单）（助攻：璐璐）。
主人被对面的 诺手（上单） 击杀了。
```

分路是给模型的**上下文**，不是播报文案的固定部分——模型自己决定说不说。
普通匹配、大乱斗一律不补（数组顺序不保证，补上去就是编的）。

**助攻**：主人击杀、主人被杀时会带上助攻者，格式是
「主人击杀了对面的 诺克萨斯之手（助攻：星籁歌姬）」。数据来自
`ChampionKill` 事件的 `Assisters` 数组；为空或接口没给时整段省略，
不会留下空括号。

- 写成**数据式**（`助攻：A、B`）而不是叙述式（`有 A、B 帮忙`）——
  叙述句模型很容易照念一遍。
- 有助攻时，提示语尾部会追加一条约束：**「助攻只作背景，不用特意点名
  谁帮的」**。所以猫娘一般不会主动念"是某某帮你的"，主人问起才细说。
- 击杀者和被杀者不会出现在助攻名单里（防止"被 Zed 击杀（助攻：Zed）"）。
- **辅助位那条助攻播报**（`主人助攻，X 拿下了对面的 Y`）不加这条约束 ——
  它本身就是在说助攻，再要求"别提"会自相矛盾。

> ⚠ 国服是否真的填 `Assisters` 还没在真机上确认过。开局跑一次
> `python smoke_live.py` 看它打印的「最近一条 ChampionKill 的原始字段」
> 就知道——那里会明确告诉你字段在不在、是不是空数组。

**分路对位**：接口**不提供** lane/role 字段，但排位和灵活排位里
`allPlayers` 同队内部的顺序固定是 **上单 → 打野 → 中单 → ADC → 辅助**，
所以开局能说清你走哪路、对位是谁。

- 只在**召唤师峡谷 + 征召模式**生效，大乱斗等自动跳过
- 敌方人数不足（秒退、自定义局）时不硬凑对位
- 认不出主人时不猜分路
- ⚠ 普通匹配没有位置选择流程，顺序不保证 —— 常玩普通匹配请设
  `infer_lane_positions = false`
- 中英混排会自动留空格（`对面的 Darius`），中文名不加（`对面的亚索`）


**对局时间**：格式是 `时:分:秒`（如 `00:11:05`、`01:05:30`）。早先用
`分:秒`，`10:00` 容易被念成"十点整"或"十比零"。

**只有这几类带时间**：一血、对局结束、定期小结、赛后总结。

开局 / 团灭 / 小龙 / 大龙 / 峡谷先锋 / 推塔 / 破兵营 / 别人多杀 **都不带** ——
这些事件本身已经说清"发生了什么"，再挂一个时刻只是占篇幅（实测模型的
40 条 LOL 回复里只有 2 条会提时间，带着也基本用不上）。地图·模式仍会保留，
模型靠它确定场景。

**战绩行**：有的播报会附上主人此刻的 `英雄，K—D—A，N 级`：

| 带战绩 | 不带战绩 |
|---|---|
| **团灭** | 开局、对局结束、一血、小龙、大龙、峡谷先锋、推塔、破兵营 |

- **只有团灭带**：一血、小龙、大龙、先锋、塔、兵营都不带（2026-11-17
  用户指定）。这些时刻本身已经够清楚，再跟一行"主人现在 X—Y—Z"是多余的尾巴。
- **还有冷却**：距离上次带战绩的播报不足 `stats_cooldown_seconds`（默认 60 秒）
  时也省掉。数字仍可从小结/赛后总结/聊天查询拿到。
- **塔/兵营/先锋不带**：它们是环境档，量大、多是背景进展（"敌方拆了座
  塔"），播报越短越好。
- **开局不带**：那一刻必然是 `0—0—0，1 级`，写出来只是噪音。
- **对局结束不带**：5 秒后的赛后总结会给完整战绩，这里重复没意义。

只带 KDA 和等级，不带补刀和复活倒计时（那是屏幕上的数字，说出来只会
拖长句子）。

**塔的位置**按结构名解析（国服实测格式 `Turret_TChaos_L0_P3_...`）：

- `L0 / L1 / L2` = 下路 / 中路 / 上路
- **嚎哭深渊（大乱斗）只有一条路**：塔名不带路名，只说「外塔/二塔/高地塔」
- `P3 / P2 / P1` = 外塔 / 二塔 / 高地塔
- `P5 / P4` = 门牙塔（不带路名）

### 特殊播报

**超神**：连续 8 杀不死时，那一句加「主人超神了！」。之后继续杀不再重复。

**差一个头超神被终结**：7 连杀时阵亡，加「被终结了，可惜还差一个人头
就能超神。」

**龙魂**：本局**第 3 条被击败的小龙**的属性就是本局龙魂（不分哪方拿的）。
某方累计拿满 4 条即获得它。

- 第 3 条：`主人这边已经三条龙了，再来一条就是火龙魂`
- 第 4 条：`主人这边拿到第四条，火龙魂到手了`
- 远古巨龙不参与龙魂，也不计入总数

> **计数细节**：龙魂按"本局第 3 条被击败的小龙"锁定（不分哪方）。
> 认不出击杀者阵营的龙**仍然计入总数** —— 阵营只影响"谁拿的"，不影响
> "这是第几条"。同一条龙的事件被重复投递时会去重，避免把龙魂锁定到
> 更早的龙上。日志里每条龙都带全场序号（`[小龙] 本局第 N 条…`），
> 对不上时可以逐条核对。

### 连杀播报

**主人自己的三杀以上**：播一句，且**走关键档**（值得打断当前话题）。
措辞不带战绩、不带对局时间 —— 五杀本身就是最高光，加一行数字反而稀释。

**别人的三杀以上**：也播一句，走常规档（背景音）。

两边都做了同一件事：接口对一次五杀会**连发 2/3/4/5 四条** Multikill，
逐条播就是"三杀→四杀→五杀"连说三句。所以攒 4 秒取**最高**那条，只播一句。

- 双杀太常见，谁的双杀都不说。
- 主人的五杀**不会**被拆成三杀/四杀/五杀三条（实测踩过这个坑）。

```toml
others_multikill_min_streak = 3     # 几杀起才播；0 = 完全不播
others_multikill_settle_seconds = 4 # 攒多久取最高
```

主人**自己**的 `Multikill` **从不单独播报** —— 它只用来取「三杀/四杀/五杀」
这个标签，因为 `ChampionKill` 已经把每个人头都说过了。

### 播报频率

实测：**15 分钟的真实对局（10 个事件）播报 9 条，平均 100 秒一条。**

两个可调参数：

```toml
normal_gap_seconds = 3.0    # 调大 → 常规档更克制
window_seconds = 10.0       # 调大 → 环境档攒得更久、合并成更少的话
```

> 代价要说清楚：播报走 `ai_behavior="respond"`，**每条会真的跑一次模型
> 并出声**。关键档越多，模型调用越多。

想听全场战况（包括队友和对面的人头）就把 `only_my_events` 设成 `false`。

播报走的是 N.E.K.O 的正规通道（`ai_behavior="respond"`），所以猫娘是
**带语音**说出来的，不是只弹文字。

### 在聊天里问战况

三个 LLM 工具，直接跟猫娘说话就会触发：

- "我这局打得怎么样？" → 实时 KDA / 补刀 / 经济 / 等级 / 装备 + 双方比分
- "对面亚索发育怎么样？" → 查指定英雄或玩家（支持官方全称或英文英雄名）
- "刚才发生了什么？" → 本局最近的事件记录

### 面板：逐项开关播报

插件管理器里点开「英雄联盟陪玩」→「播报设置」，可以一项一项开关：

- **对局开始 / 一血 / 我的击杀 / 我的阵亡 / 主人助攻（辅助位）/ 多杀 / 团灭**
- **小龙 / 大龙 / 峡谷先锋 / 推塔 / 破兵营 / 对局结束**
- **定期战况小结 / 赛后总结 / 分路里程碑**
- **干跑开关**（只写日志，不让猫娘开口）
- **在聊天里显示提示文本**（默认关）

面板按用途分成三组（人头与战况 / 地图资源 / 对局与提醒），分组表由 Python 侧
`event_groups` 下发，TSX 不维护第二份。

改动**立即生效**，并会尝试写回配置（重启后保留）。如果宿主拒绝写配置，
面板仍然会生效，但会如实回报"未持久化"——重启后会回到配置文件里的值。

面板结构：

1. **当前状态卡**——两排指标：对局 / 对局时间 / 已开启播报数 /
   我的分路 / 对位英雄 / 排队中。下面一行是状态徽章和当前比分。
2. **三个标签页**
   - **播报开关**：按「人头与战况 / 地图资源 / 对局与提醒」分组，每组标题带
     `3 / 6 开` 这样的摘要；宽屏下自动并排（`Columns fluid`）
   - **分路里程碑**：开关 + **当前进度**（带完成度进度条）+ 各分路判定条件
   - **运行参数**：节流参数、接口地址、分路推断是否可用

### 提示文本在聊天里显不显示

播报走 `push_message`，其中两个参数是**独立**的：

| 参数 | 作用 |
|---|---|
| `visibility` | 只决定**看不看得到**（`[]` / `["chat"]` / `["hud"]`） |
| `ai_behavior="respond"` | 决定模型**读不读、回不回**（这里一直是 respond，带语音） |

所以关掉 `show_prompt_in_chat`（默认）时 `visibility=[]`：**猫娘照样读出整段
内容并带语音回应，只是聊天窗口里不会出现那段括号提示**。

```toml
show_prompt_in_chat = false    # 默认；想要调试就设 true
```

面板「测试」页里也有这个开关。打开后聊天里能直接看到模型收到了什么，
适合排查"为什么这句话说得不对"。

> 面板只使用**运行时里真实存在**的组件。这个运行时不是 React，import 到
> 不存在的导出会让面板整块白屏，且报错只出现在宿主控制台。测试里有
> 一条 `test_panel_only_uses_verified_components` 守着这份名单，同时也防
> 「给 `StatCard` 传 `hint`」「给 `KeyValue` 传 `label/value`」这类
> 传了但不显示的问题。

> 面板用的是 Hosted TSX（`ui/panel.tsx`，在线编译）。它跑在
> `sandbox="allow-scripts"` 的 iframe 里，裸 `fetch` 会被不透明源拦掉，
> 所以所有交互都走 `props.api.call` → Python 侧的 `set_announce` /
> `set_dry_run` 入口。
>
> **面板文案全部内联中文**，不查语言包。原因：用 `t()` 时要赌宿主 locale
> 能否解析到 `zh-CN`，一旦落到别的语言就会显示英文甚至原始 key。选项文本
> 不该由 locale 决定。事件的中文名由 Python 侧 `_EVENT_LABELS` 经 context
> 下发，保证面板显示的和日志里用的是同一套名字。

### 三个手动入口

| 入口 | 作用 |
|---|---|
| 陪玩状态 | 看是否连上、在不在局内、队列里积压了多少、最近播报了啥 |
| 立刻说战况 | 不等定期小结，马上让猫娘点评一次 |
| 连接自检 | 直接探测接口，报告走的是 https 还是 http。排查时先跑这个 |

## 配置

改用户数据目录里的那份（**不是**插件源码目录里的）：

```
%LOCALAPPDATA%\N.E.K.O\plugins\neko_lol\config\plugin.toml
```

第一次运行时宿主会从 `config.example.toml` 复制一份出来。每一项都有默认值，
删掉任何一行都不会让插件坏掉。

配置项的中文名和说明定义在 `config.schema.json` 里（`x-title-i18n` /
`x-description-i18n`），插件面板按它渲染。**改配置项时必须同步改这个文件**，
否则那一项在面板上会退化成裸 key。

最常调的几项（**完整清单见 `config.example.toml` / `config.schema.json`**）：

```toml
[neko_lol]
# ── 播报节流 ─────────────────────────────────────────────────
# 常规档两条之间至少隔这么久（秒）
normal_gap_seconds = 3.0
# 环境档攒多久一起说（秒）
window_seconds = 10.0
# 一次合并最多列几条，超出折叠成"等共 N 条"。
merge_max_items = 6
# 战绩行冷却（秒）。0 = 每次都带。
stats_cooldown_seconds = 60.0

# ── 节奏 ─────────────────────────────────────────────────────
# 在局内的轮询间隔（秒）
poll_interval_seconds = 2.0
# 不在局内时的轮询间隔。局外每次探测都是白跑，所以默认降频到 5 秒
idle_poll_interval_seconds = 5.0
# 摘要：对局第 15 分钟首播，之后每 5 分钟一次（按对局时间，不是墙钟）
summary_first_at_seconds = 900.0
summary_interval_seconds = 300.0
# 嚎哭深渊系（大乱斗 / 海克斯大乱斗）单独一套节奏
aram_summary_first_at_seconds = 480.0
aram_summary_interval_seconds = 180.0
# ── 爆发小结 ────────────────────────────────────────────────
# 15 分钟后，30 秒内 ≥5 个人头就补播一次小结（同一拍有团灭则跳过）
summary_burst_after_seconds = 900.0
summary_burst_kills = 5
summary_burst_window_seconds = 30.0
summary_burst_cooldown_seconds = 60.0
# 大乱斗人头密度高，门槛单独一套
aram_burst_kills = 8
aram_burst_cooldown_seconds = 120.0
# 判定"对局结束"前要连续拿不到数据多久（秒）。
# 调小会让客户端抖一下就放出假的赛后总结。
game_over_grace_seconds = 20.0

# ── 内容筛选 ─────────────────────────────────────────────────
# 只播主人自己的事：队友击杀/阵亡、对面互杀都不播。
# 设 false 才会听全场战况。
only_my_events = true
# 按名单顺序推断分路，开局说清你对位谁。只有排位/灵活排位成立。
infer_lane_positions = true
# 别人三杀以上才说
others_multikill_min_streak = 3
# 第一次装建议设 true，只写日志不开口
dry_run = false

# ── 大乱斗降噪 ───────────────────────────────────────────────
# 人头/阵亡走环境档（一波团合并成一句）；死亡只播"连杀被断/连着倒两次"
aram_kills_ambient = true
aram_death_only_notable = true

# 完全不想听某类事件
[neko_lol.announce]
turret_killed = false
```

其余值得知道的几项：`enabled`（总开关）、`base_url` / `allow_http_fallback` /
`http_timeout_seconds`（接口地址与回退）、`user_chat_quiet_window_seconds`
（用户在聊天时静默多久）、`post_game_summary`（赛后总结总开关）、
`join_replay_max_game_time_seconds`（中途加入判定）。

> **TOML 分段陷阱**：一旦写了 `[neko_lol.announce]` 这种子表，后面的裸键就
> 都归子表了。加新配置时把标量键写在子表**之前**。插件启动时会检查有没有
> 读不到的键并写进日志，改完扫一眼日志就知道有没有写错位置。

### 英雄名：接口给的是官方全称

**国服接口返回的是中文官方称号**（「虚空恐惧」「诺克萨斯之手」「德玛西
亚之力」），四个字、不像人话；国际服可能返回英文（`Yasuo`）。

播报提示语已经要求猫娘换成玩家平时的叫法，所以**语音里听到的是「大虫
子」「诺手」这类**。但「陪玩状态」这类直出文本仍会照抄官方全称。

想让直出文本也变口语，在插件数据目录放一个 `champion_aliases.json`：

```json
{ "虚空恐惧": "大虫子", "诺克萨斯之手": "诺手", "德玛西亚之力": "盖伦" }
```

路径：`%LOCALAPPDATA%\N.E.K.O\plugins\neko_lol\data\champion_aliases.json`
（文件不存在就用接口原样，不会报错。国际服也可以用同一个文件把英文换成
中文，键写英文名即可。）

## 国服注意事项

- 游戏装在 `D:\WeGameApps\英雄联盟` 这类 WeGame 目录下也能正常工作 ——
  本插件只连本地回环端口，不依赖安装路径。
- 接口的证书是自签的，插件已关闭证书校验（这是访问该接口的标准做法）。

### ⚠ 安全软件会给本地连接叠加延迟（这台机器上已实测）

在本机上实测：**任何被拒绝的本地连接都固定延迟约 2.05 秒**——用原始
socket 打 `127.0.0.1` 的任意空闲端口（2999、59999 都一样）都是这个数。
这是防火墙过滤驱动（火绒安全、游戏加加这类）的典型行为，与本插件无关，
也不影响对局中的正常请求（局内响应是毫秒级）。

它带来的可见影响只有一个：**没在打游戏时，每次探测约 4 秒**
（https 试一次 + http 回落试一次）。插件已经为此做了两件事：

- 局外降频到 5 秒一探（`idle_poll_interval_seconds`）
- 探测慢于定时器时跳过该跳，绝不让两次轮询重叠（并发的两次轮询会
  同时读事件游标，把同一个事件播报两遍）

所以**判断"能不能连上"的依据是「有没有干净地报出被拒绝」，而不是快不快**。

如果「连接自检」报的是**超时**而不是被拒绝，那才是有东西在静默丢包——
把 N.E.K.O 加进安全软件白名单，或者临时关掉加速器再试。

## 排查

1. **猫娘一声不吭** → 先调「连接自检」。能读到对局时间说明链路是通的，
   再去查是不是被节流了（看「陪玩状态」里的队列积压）。
2. **不确定是不是环境问题** → 在插件目录下跑 `python smoke_live.py`。
   它直接打真实端口，不走任何 mock，几秒内就能分辨"没开游戏（正常）"、
   "被拦截（超时）"和"能读到数据"三种情况。
3. **重复播报同一件事** → 不正常，把插件日志发出来。插件用 `EventID`
   游标去重，理论上一局内每个事件只播一次。
4. **插件在中途重载后整局静音 / 疯狂重播** → 看 `join_replay_max_game_time_seconds`。
   插件靠"对局已进行多久"判断是开局还是中途加入。
5. **日志位置**：`%LOCALAPPDATA%\N.E.K.O\logs\plugin\` 下按插件 ID 命名。
   把 `NEKO_LOG_LEVEL` 设成 `DEBUG` 能看到更详细的仲裁决策。

```
├── run_tests.py         跑全部离线测试
├── smoke_live.py        真机自检：直接打真实端口
├── sim_instant.py       时序仿真：量事件从发生到说出口的间隔
└── tests/               离线测试（假 API 驱动完整状态机）
```

设计上刻意把「拿数据」「解析」「措辞」「什么时候说」拆成四个模块：
播报逻辑最容易出问题（重复、刷屏、抢话），拆开之后每一层都能单独测。

### 已知限制

- **胜负以 `GameEnd` 为准**。对局结束事件带 `Result`（Win/Lose/Draw），
  赛后总结直接用它。**没收到 `GameEnd` 时完全不提输赢** —— 击杀数领先
  不代表赢了（可能被偷家），猜错比不说更糟，所以只报战绩和过程。
- **`game_end` 和 `post_game` 分工**：前者只说"这局结束了"，后者说胜负和
  完整战况。同一条 `Result` 不会被说两遍。
- **赛后总结等 5 秒，不等数据消失**。收到 `GameEnd` 就说明对局结束了，
  5 秒后直接播总结（留 5 秒是让最后一批人头/推塔事件落地）。没收到
  `GameEnd` 时（比如中途退出）才由"数据持续消失"那条判定兜底。
- **经济是估算的**。接口不给累计经济，用「手上金币 + 已购装备价值」近似。
- **不做历史战绩**。查最近 N 把的战绩需要走 LCU 接口（要读客户端 lockfile
  凭据），当前版本没接。想要的话可以加。
- **英雄名靠模型转口语**。接口给的是中文官方全称（如「虚空恐惧」），插件
  不在代码里做映射表，靠提示语让模型换成「大虫子」这类叫法；想要直出文本
  也稳定，就在数据目录放可选的 `champion_aliases.json`。
- **中途重载后计数从 0 开始**。接口不给"当前连杀数"和小龙总数，插件只能
  自己数。重载后本局的超神/龙魂判定可能晚一次，日志里会写出来。
- **一血只播主人拿的**。`FirstBlood` 事件的 `Recipient` **是拿到一血的人**
  （2026-11-16 实测确认），所以「主人拿到一血」能准确判断；主人被杀那种
  情况该事件本身不提供。`only_my_events = false` 时才会报"对面拿走了一血"。
- **大乱斗的塔名格式未实测**。嚎哭深渊按 `mapNumber == 12` 识别，塔名去掉了
  路名；但真机上大乱斗的结构名是否也是 `Turret_T*_L*_P*` 格式，我没有验证过。
  如果格式不同会回落成「一座防御塔」，日志里会打 `[结构物] 解析不出路`。

### 宿主耦合（部分未核实）

以下几处依赖 N.E.K.O 宿主的运行时接口。它们在代码里都有降级路径，但
**没有在真实宿主上逐一验证过**：

| 接口 | 用途 | 失败时的行为 |
|---|---|---|
| `push_message` | 所有播报 | 异常被捕获并写日志，插件继续跑（只是不吭声） |
| `@message(source="chat")` | 用户聊天时静默 | 装饰器缺失时降级成空操作，等于没有静默窗口 |
| `ctx.update_own_config` / `config.update` | 面板开关持久化 | 两条路径都试；都失败则仅本次运行生效，返回 `persisted: false` |
| `@timer_interval` | 轮询驱动 | 没有降级 —— 定时器不跑就完全不工作 |

`@timer_interval` 是唯一没有兜底的：如果宿主不调用它，插件不会有任何反应。
